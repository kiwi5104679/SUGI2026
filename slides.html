Introduction

背景と目的

  • QuartoはMarkdownを基にしたドキュメント作成ツールである。
  • 文章の中にコードと実行結果を表示でき、統計解析のレポーティングに有用である。
  • 近年の統計プログラミング業務ではSASとRを併用するケースが増えているが、
    Markdownにおける複数言語の利用はコード実行や管理を複雑化させる。

本発表では、RとSASを連携する技術の変遷を概観し、
両言語を両立したレポーティング手法を整理することを目的とする。

本発表で扱う3つの方法

アプローチ 仕組み SASの実行環境
Quarto単体 knitr SASエンジン ローカルSAS
SASmarkdown knitr SASエンジンの拡張 ローカルSAS
sasquatch SASPy + reticulate ローカル / リモート（SAS OnDemand等）

Quarto単体のSASコードブロック

Quarto単体のSASコードブロック

  • Quartoは{knitr}のエンジン経由で、{sas}コードブロックを実行できる
  • RチャンクとSASチャンクを使い分けることで、同一ドキュメント内に記述できる。
  • ただし、内部でローカルのSASを呼び出すため、Rと同じマシンにSASがインストールされている必要がある

sasquatch

sasquatch

  • rOpenSciのRパッケージ
  • SASPy（Python）＋ reticulate経由でSASセッションと連携する
  • SAS OnDemand for Academics (ODA)をはじめとするリモートSASにも接続可能
  • sas_from_r() / sas_to_r()でRとSAS間のデータ受け渡しが容易

以下は初期設定のためのCodeであり、Quarto documentに含める必要は無い

```{r}
#| eval: false
library(sasquatch)
sasquatch::install_saspy() 
sasquatch::configure_saspy()
```

以下のような.py fileを設定することが必要。こちらもdocumentには不要

```{python}
#| eval: false
SAS_config_names = ['config_name']
config_name = {
  'saspath': '/CHBS/apps/SAS/SAS9.4M8/SASHome/SASFoundation/9.4/sas'
}
```

Chunk optionの記述方法

R/SASmarkdownではChunk optionの冒頭に#|を記述する必要がある

```{r}
#| eval: false
print("Test")
```

Quarto SAS/sasquatchでは冒頭の#|の代わりに、冒頭に*|を、末尾に;を付与する必要がある。

```{sas}
*| echo: fenced;
proc means data=sashelp.cars;
  var mpg_city mpg_highway;
run;
```
Error in `sasquatch::sas_run_string()`:
✖ No active SAS connection.
ℹ Use `sasquatch::sas_connect()` to start a new SAS session.

Quarto単体のSAS コードブロック 設定方法

  • SASのPathをymlにて記述する必要がある
engine: knitr
knitr:
  opts_chunk:
    engine.path:
      sas: "/CHBS/apps/SAS/SAS9.4M8/SASHome/SASFoundation/9.4/sas"

SASmarkdown 設定方法

sas, saslogなどのコードブロックを使用する前に、engine名やSASのPathを設定する必要がある

library(SASmarkdown)
saspath <- "/CHBS/apps/SAS/SAS9.4M8/SASHome/SASFoundation/9.4/sas"
knitr::opts_chunk$set(
  engine.path = list(
    sas         = saspath,
    saslog      = saspath,
    sashtml     = saspath
  ),
  comment = NA
)
